# ML 辅助 Agent-1 人名跨度标注 POC

状态：已通过评审，采用「试点优先」的概念验证方案。本 POC 不替换
`twostage/rules.py`；它先建立可信的质量测量，也允许最终得出「保留规则」的结论。

## 1. 问题

Agent-1 当前约有 7,000 行 jie 作用域规则，底层模型是文言文 UPOS，而非人名
NER。现有 97.2% 指标只是与含噪 v1 的兼容率，不是真正的精确率/召回率。约
28% 的规则输出不与 v1 重叠，其中同时包含真正补漏和误报。

主要瓶颈是可信标签，而不是模型架构。直接用 v1 训练会把 rules-only 补漏标成
负例 `O`。因此第一交付物是经审计参考集与可靠评分，而不只是模型。根据下述
「不要求用户独立盲标」永久政策，后续新参考集采用 Copilot A/B 加 focused review；
其结论资格由冻结协议决定，而不是由标注者身份决定。

## 2. 范围

- 只处理 Agent 1（人名下划线位置）；Agent 2 身份识别不变。
- 最终输出仍只标正文。
- 胡三省注与译文可为正文提供有界证据，但注文本身不是输出。
- POC 必须能由一位标注者在单块 GTX 1070（8 GB）上完成。
- 不一次性替换规则，不宣称 100% 自动化，不启动全语料规则重建。
- 最终交付物是可独立运行的本地 ML 标注模型。Copilot 只用于开发期加速标签生产，
  不是生产标注器，也不是运行时依赖。

## 3. 证据与标签

候选通道包括 v1、当前规则、段落作用域译文、同 jie 注文投射，以及后续模型。
它们彼此相关，只是候选生成器，不是独立投票，也不是真值。

训练标签采用有界的裁定后并集：

- v1/规则精确一致项可按 `agreement` 来源自动信任。
- 分歧分层抽样审计，上限为训练 3,000、dev 800 个跨度。
- `note-only`、`translation-only` 必须逐跨度由用户 focused review 确认，不能只凭
  类别策略传播。
- Copilot-assisted 标签可进入训练，或进入另行声明的锁定评估。必须记录真实
  provenance，不得冒充纯人工标注。

### 3.1 注文与译文护栏

1. **Agent 1 不接触身份数据。** 注文人名在摄入前清洗为
   `{note_index, after, start, end, surface}`；Agent-1 代码从不加载或序列化
   `person_id`。
2. **仅限同一 jie。** 注文证据不得播种其他 jie，也不得形成 juan/语料级人名表；
   注文派生表面始终禁止跨 jie 复用。
3. **译文保持原批准范围。** 段落批准的译文证据在组装 jie 后仍只能作用于原段落。
4. **更早锚点否决。** 注文/译文不能独自授权单字或 given-name 回指；仍必须有
   同一 jie 内更早的正文锚点。
5. **仅几何，不做身份。** 证据只能提示「是人」和边界；注文措辞不成为正文标签。

译文只离线使用。胡三省注属于公有领域源文，因此后期可做默认关闭的运行时
A/B，但不属于当前 P0。

### 3.2 Copilot teacher 与辅助标注闭环

P2 可使用版本化的 Copilot 标注器作为 annotation **teacher**。它的职责是降低人工
标注成本、改进供目标 ML 模型训练的标签语料。Copilot 准确率与目标模型准确率必须
分别测量。

- 已完成的三个试点 juan 可作为边界政策和跨度几何示例；它们是开发上下文，不是
  密封数据。
- teacher 可读取当前整卷全文以理解叙事，但证据授权以 jie 作用域为更高优先级。
  示例表面和其他 jie 上下文不得形成整卷人名表；同卷另一 jie 的相同表面、锚点或
  推断身份不能授权当前候选。每个建议都必须在目标 jie 内成立，且不得读取身份 KB。
- 新的 P2 assisted round 不加载 v1、规则或身份字段。Copilot teacher 可读取当前
  jie 的胡三省注文原文，也可临时读取批准来源的现代汉语译文；译文必须通过已审计
  来源哈希校验，并唯一对齐到当前段落或 jie。译文原文不得写入仓库或 round pack。
- 注文与译文只是证据，不是输出。它们只能在批准作用域内帮助判断正文人物性与姓名
  几何；单字或 given-name 回指仍须同一 jie 内更早正文锚点，任何证据都不得形成
  跨 jie 人名表。
- 候选来源必须记录 Copilot teacher 版本、prompt/示例哈希、注文/译文来源哈希、
  目标 jie 作用域，以及「可见整卷上下文但不得授权」这一事实。保存的 teacher 输出
  只能包含正文候选几何，不能包含注文或译文原文。
- 早期设计曾规定每五卷保留一卷无候选人工 blind anchor。该设计只作为历史记录；
  按 3.3 节永久政策，今后不得再次把这种任务分配给用户。
- 低负担 diagnostic 轮次使用两个互不可见、互不读取输出的 Copilot pass：A 偏召回，
  B 偏精确边界。两遍精确几何一致且均非显式低置信时可自动接受；单边几何、显式低
  置信和冻结 ML 模型独有项必须进入人工 focused review。主流程必须重新验证两遍
  schema、channel、provenance、task inventory 和几何，不能信任 teacher 自报验证。
  为训练抽取的整批标签仍只能进入训练，因为拿它评估会污染 split，而不是因为
  Copilot 参与了标注。
- 训练用 assisted 标签不得进入 dev 或锁定评估。另行抽样、对候选模型盲化的
  Copilot A/B 评估集只用于评估，并必须记录明确的 Copilot-assisted 来源。其属于
  diagnostic 还是 formal、能否支持晋升，须由冻结的抽样设计、审核、统计功效和预先
  声明的决策门槛独立决定。

Copilot teacher 的改进闭环为：

1. 冻结 teacher 版本 `N`，只生成一批新的 assisted 数据；
2. 独立执行 A/B 两遍，自动接受合格精确共识，只人工审核分歧、显式低置信和
   model-only 补漏项；
3. 冻结 focused review 纠错结果，计算双遍共识的精确 P/R/F1、重叠诊断、新增、删除及一对一
   几何替换；
4. 按边界政策、单字照应、角色/专称、外族称号、标点及其他预先声明的挑战分层
   归类错误；
5. 只根据已完成的人工纠错修改 teacher 指令与示例，形成版本 `N+1`；
6. 后续 teacher 不得重新生成或覆盖已经完成的批次。

Round 4 前的首个双遍批次共 20 jie、302 个 union candidates：277 个合格精确共识
自动接受，人工只审 25 个（8.3%），最终冻结 284 个跨度。相对最终标签，双遍共识
精确率为 99.64%、召回率为 97.18%；该数值来自同一 assisted 批次的 focused review，
只能用于 teacher 诊断。已确认示例包括：`其母/母曰` 不标；同 jie 唯一化的
`[使者]/[楚使者]` 标注且 `御` 留在线外。

目标模型闭环只摄入 focused review 纠正后的 assisted 标签，并训练新的独立模型。
teacher 改进在下一批 focused-reviewed assisted 数据上测量。目标模型可在已锁定、
对候选模型盲化的 Copilot-assisted 评估集上比较。Copilot 参与本身既不会取消、也不会
赋予晋升资格；只有独立冻结的协议、样本量、审核及预先声明的决策门槛足以支持时，
比较结果才能授权晋升。

### 3.3 不要求用户独立盲标的永久政策

永远不要求用户独自对无候选正文做穷举盲标。该约束适用于重复 P0、blind anchor、
dev 更新及 P3 评估。

1. **「盲」指对候选模型盲化，不代表必须纯人工。** 参考标签锁定前，两个 Copilot
   pass 都不得读取 v1、规则、目标模型预测、另一 pass 输出，或该样本既往评估错误。
2. **Copilot 执行两个独立 pass。** A 偏召回，B 偏精确边界；两者只接收冻结的正文、
   几何和绑定边界政策。主流程独立校验 schema、任务清单、provenance 和精确几何。
3. **用户只做 focused review。** 双遍精确一致且均非显式低置信的项可自动接受；
   用户只审分歧、显式低置信及预先声明的抽审样本，永不承担空白正文穷举 pass。
4. **推理前锁定。** 抽样、任务、pass 版本、prompt/政策哈希、共识、focused 决定及
   最终几何必须在生成任何候选模型或规则预测前冻结。
5. **结论资格取决于协议，而非标注者身份。** Copilot 参与不是把
   `formal_evaluation` 或 `eligible_for_promotion` 设为 false 的自动理由。每个集合
   必须在推理前声明 diagnostic/formal 状态，并绑定抽样框、独立性控制、审核政策、
   统计功效要求和晋升门槛。低功效且没有预声明晋升门槛的 diagnostic 只因这些原因
   不具晋升资格。
6. **不得静默升级要求。** 更强结论需要更强且独立冻结、对候选模型盲化的协议和审核。
   本项目通过增加 Copilot A/B 抽样与 focused review 满足该需求，不把空白正文穷举
   盲标负担转回给用户。

## 4. P0 参考集

本节只记录已经完成的历史 P0 协议，不得重复其中的用户独立盲标；未来所有参考集
生产均遵循 3.3 节。

选取三个 juan：

1. 一个固定种子随机 juan；
2. 一个 rules-v1 精确几何分歧率最高的 juan；
3. 一个 feng、可汗/单于等罕见结构密集的挑战 juan。

标注者首先只看空白正文，完全不知道任何候选。第二遍强制展示候选并集用于补漏。
7–10 天后，对约 10% 的连续 jie 盲重标以测量自一致性。这三个 juan 是试点参考，
不是密封测试集，并从未来密封测试的抽样框中排除。

绑定边界准则对前置称号采用**有显式姓名时只标姓名核心**：
`赵王[虎]`、`大将军[光]`、`弟[亮]`。前置爵位、官职和亲属词留在线外；
但约定的后置外族/后妃称号构成完整人物表面时整体标注：
`[阿波可汗]`、`[沙钵罗叶护]`、`[王皇后]`；若称号在姓名前，仍只标姓名核心，
如 `柔然可汗[阿那瓌]`。
若只有 `始皇` 等独立专称，该专称本身可作为人物核心。复姓与完整给名仍在线内。
`帝/太后` 等纯角色表达只在当前句法明确指向一个具体人物时标注（`[帝]曰`、
`[太后]怒`）；泛指、类别和授予称号的用法不标，身份由 Agent 2 解析。
这与部分当前规则的完整表达几何有意不同。
可独立识别的人名或个体专称即使嵌在建筑、官署、器物或关系复合词中，仍属于人物
核心，例如 `[汉高]庙`、`[启]母神`。只标人物核心，`庙/府/宫/印` 等载体词留在
线外；机构名中的普通角色词不会仅因此获得授权。
单一命名谓词仍只标结果（`字[季]`、`更名曰[询]`）。若 `姓 X 字 Y` 等连续结构
共同给出当前唯一完整称名描述，而各部分无法独立构成该描述，则标完整表达，例如
`即常安[姓武字仲]`。
并列人物共享右侧称号时，按每个具体人物在原文中实际出现的表面分别标注，包括省略
共享称号的前项：`乌孙[大]、[小昆弥]`、`[广平]、[巨鹿]、[乐成王]`。任何带数量词
或 `诸/群/众` 等复数标记、当前明确指向多人的表面都是硬否决，即使同 jie 已锚定
全部成员也不标共享角色核心：`万安、咸宜二公主` 只标 `[万安]`、`[咸宜]`，
`二公主/公主/咸宜二公主` 均不标。juan 标题属于元数据而非叙事人物指称，一律
不含人物跨度。
当前 jie 若以一个具体但未具名的角色引入唯一叙事人物并持续回指，可标该角色表面，
如 `[神策军将]诉事…擒[军将]…[军将]已死`。`陛下/足下` 等纯代词式敬称和
`妪` 等临时辱称不标。`向氏/金氏` 明确指单个人物时可标，`桓氏` 等宗族整体不标。
族名本身不标；`黠戛斯可汗` 只有在明确指具体在位者时才可整体标。
授官、册立、自立、赐谥所产生的新头衔仍不标，后文成为稳定人物指称后才标。
人物 span 与未来 entitlement 时间线分层保存，不为记录授号事件而扩张 PERSON。

## 5. 几何与评估

- 按生产规则相同方式组装编号 jie，以硬分隔符保留段落边界。
- 长序列使用重叠窗口，每个字符只有一个最居中的归属窗口。
- 预测与评分单位仍是一个目标 jie。模型窗口可包含多个周边 jie 作为较弱叙事上下文，
  但非目标字符标签必须为 `-100`、不拥有输出，也不能形成跨 jie 跨度。
- BIO 只允许合法转移；`O` 后的孤立 `I-PER` 提升为 `B-PER`。在没有标点、符号、
  数字、硬分隔符或非归属边界时，train/dev 已固定的结构解码器会把紧邻活动人物
  跨度的 `B-PER` 合并为连续跨度。跨度不得跨硬分隔符或从非归属字符开始/结束。
- 主指标为精确 `[start,end)` PER P/R/F1；重叠 P/R/F1 只作诊断。
- 两者都采用一对一最大匹配，一个长预测不能匹配多个参考跨度。
- 随机与挑战 juan 分开报告，并按结构分层。
- 把完整表达→姓名核心差异单列为**几何替换**，不得混入新增、删除、遗漏或误报。

### 5.1 多 jie 模型上下文

上下文大小由模型 token budget 决定，不固定为 `±1 jie`。先为完整目标 jie 保留空间，
再按距离从近到远填入前后 jie。因此短目标可以看到多个周边 jie，长目标可能只能看到
很少或没有额外上下文。

- 保留明确的段落与 jie 边界，并记录每个上下文 jie 相对目标的有符号距离。
- 上下文可帮助神经模型理解叙事连续性，但不得产生确定性的跨 jie 锚点、表面传播、
  身份解析或输出跨度。
- 先训练和评估 target-jie-only 基线，再比较 target-only、有限邻近上下文和最大
  token-budget 上下文；所有指标只按目标 jie 精确几何计算。
- 上下文构造与 checkpoint 选择只能使用训练集和 challenge dev 固定；不得根据随机
  试点 holdout 或密封集选择上下文大小。
- 根据实际上下文图建立对称 guard band。任何训练窗口都不得包含 dev 目标文本，
  即使只是上下文；dev 窗口中可见的 jie 也不得作为训练目标。必须报告 guard-band
  排除项。
- 先使用现有 Transformer。只有有限 Transformer 上下文已证明有效且 512-token
  限制确实成为瓶颈时，才 A/B 测试 LSTM、层次 Transformer、Longformer 等架构。

Tier-1 只能鼓励或证伪：随机 juan 的精确 F1 比规则低超过 3 点、遗漏恢复低于
25%，或挑战补漏无补偿回退时停止；精确 F1 在规则约 2 点以内或更高、恢复至少
50% 已确认遗漏且无系统性新误报类别时，才进入下一阶段。

正式采纳或自动发布必须基于独立抽样、对候选模型盲化、冻结审核且具有 bootstrap
置信区间的评估；Copilot 参与不是取消资格的理由。历史阈值仍为：模型精确 F1
不低于规则、90% 区间不重叠、挑战分层下降不超过 5 点，且自动发布层精确率单侧
95% 下界至少为 0.98。

### 5.2 P3 锁定、对候选模型盲化的 assisted diagnostic

在任何 P3 模型推理前，冻结五个从未使用过的完整 juan：

- 从合格的 1–294 抽样框中，以固定种子无放回均匀抽取三卷；
- 从预先声明的角色/专称正文词频最高五卷中密封抽取一卷；
- 从预先声明的外族称号正文词频最高五卷中密封抽取一卷。

排除所有曾用于训练、开发、试点 holdout、blind anchor 评估、assisted 标注或已
废弃/泄露评估集的 juan。概率样本与挑战卷都使用私有随机种子抽取；私有 manifest
必须冻结该种子、选定模型哈希、checkpoint 选择记录、选择政策、任务/来源哈希和
当前代码提交。标注任务文件只能包含无候选正文及段落/jie 几何；每卷完成并永久
锁定前，UI 不得泄露其选择角色。按 3.3 节执行 Copilot 双 pass 与 focused review，
不得给用户分配穷举盲标。五卷参考标签全部锁定前，不得生成模型或规则预测；失败案例
不得用于选择或重训被评估模型。该集合对候选模型密封；只有协议预先声明 diagnostic，
或统计功效/决策门槛不足时才保持 diagnostic，原因不是 Copilot 参与。

若完整 juan 标注工作量不可接受，可改用预先声明的紧凑 P3：抽样框仅含从未使用、
长度为 20–600 Unicode codepoint 的编号 jie；固定抽取 12 个无放回均匀概率样本，
另从角色/专称词频 top-40 与外族称号词频 top-40 中各用私有 seed 抽取 4 个挑战
jie。概率指标与 bootstrap 区间只按 12 个随机 jie 报告，8 个挑战 jie 必须分开
报告。该低功效设计不能外推到被排除的极短或极长 jie。

## 6. 若 P0 支持继续：模型

P1 朴素挑战者使用
`KoichiYasuoka/roberta-classical-chinese-base-char` 与
`AutoModelForTokenClassification`，标签为 `{O,B-PER,I-PER}`。从一开始使用

P2 Copilot teacher 不改变上述 P1 模型定义：未经 focused review 的 agent 输出
永远不能训练目标模型；后续训练轮只能加入 focused-review-corrected assisted 跨度。

初始 P1 计时基线仍为 target-jie-only。多 jie 软上下文属于独立的 P2 目标模型 A/B，
必须保持只在目标 jie 计算 loss、输出和评分。

使用独立 CUDA 环境；先在 GTX 1070 上测一个 epoch 和完整推理，再承诺时间。
预期使用 FP32 微批与梯度累积；large 模型不在范围内。

## 7. 阶段

- **P0（历史阶段）：** 三个 juan、盲标、候选补漏、自一致性子集、精确匹配器、
  约束解码器、规则真实基线；按 3.3 节不得重复其中的用户独立盲标。
- **P1（3–5 天）：** 有界裁定标签与朴素 char-BIO 挑战者。
- **P2：** 停止或通过版本化 Copilot teacher 扩大试点；分别改进 teacher 标注效率
  与独立目标模型，不再分配历史上的用户独立 blind anchor。
- **P3（仅当结果鼓舞）：** 锁定、对候选模型盲化的 Copilot-assisted 概率评估与
  挑战集；diagnostic/formal 结论范围必须由设计预先声明。
- **P4+（仅当 Tier-2 通过）：** 校准、遗漏通道、注文运行时 A/B、留出表面研究、
  多种子方差和混合部署。

## 8. 风险

- 银标偏差：使用裁定标签，不直接使用 v1。
- 长尾不可见：维护非流行度加权挑战集。
- 测试污染：密封测试失败案例不得回灌训练。
- 上下文泄漏：必须在上下文闭包完成后再划分 split；训练与 dev 窗口不得通过周边
  jie 上下文看到对方的目标文本。
- teacher 污染：锁定参考集冻结前不得展示模型/规则候选；训练用 assisted 标签不得
  进入评估；不得把跨 jie 示例表面当作当前 jie 人物证据。
- 自动化偏差：记录所有 Copilot 接受、拒绝、边界修正和 focused-review 补漏；teacher 输出
  不是真值。
- 不做用户独立盲标：按 3.3 节执行 Copilot A/B 与用户 focused review，并按真实
  provenance 报告，不冒充纯人工共识。
- 作用域/身份泄漏：预清洗注文、保持译文段落范围、执行同 jie 更早锚点规则，
  note/translation-only 逐跨度确认。
- 算力超支：先测量再安排计划。
- 劳动只是转移：比较标注/审阅与规则编写成本；POC 可以合理选择保留规则。
